# 界面文案规范

> 适用范围：本文档约束 `zh-CN` 简体中文界面文案。English 与日本語应保持相同的规则含义、信息层级和简洁口吻，但不机械套用中文字符数与固定词形。

## 1. 口吻

界面像裁判和计分板，不像旁白。

- 只写当前动作、状态或结果。
- 默认省略主语。
- 使用现在时。
- 不解释情绪，不替玩家评价选择。
- 不写世界观填充句。
- 英文只作街机版式标记，不承担规则说明。

## 2. 长度

- 主按钮：2—4 个汉字。
- 状态横幅：2—5 个汉字。
- 棋印名：2—3 个汉字。
- 棋印效果：单句；先写对象，再写结果。
- 教程提示：只写下一步操作；不超过 10 个汉字为目标。

## 3. 用词

固定名词：

| 概念 | 使用 | 不使用 |
|---|---|---|
| 单次完整流程 | 局 / Run | 冒险旅程、挑战之旅 |
| 升级物 | 棋印 | 神器、能力卡、强化模块 |
| 玩家行动次数 | 手数 | 行动力、操作点数 |
| 额外行动 | 再走一手 / 续手 | 获得一次额外操作机会 |
| 目标生命 | 王冠 | Boss 血量、核心耐久 |
| 防失败资源 | 护盾 | 生命值、容错机制 |
| 能量爆发 | 三连手 | 超载模式、终极技能 |

按钮使用具体动作：`新局`、`续局`、`重开本局`、`回到标题`、`再练一次`。不用“确定”“好的”“开始体验”。

## 4. 禁用写法

以下句式不进入游戏：

- “不仅……更……”
- “不是……而是……”式宣传对照
- 三段同构排比
- “开启 / 解锁全新体验”
- “沉浸式、颠覆性、极致、赋能、智能化”
- 伪人格提示，如“我为你推荐……”
- 开发过程、生成过程、提示词、模型或审校说明
- 失败时挖苦玩家

## 5. 视觉优先

文字删除后，界面仍应能表达主要选择：

- 升变页依靠移动图辨认马、象、车、后。
- 路线页依靠敌阵、王冠数和奖励数比较风险。
- 棋盘依靠颜色、几何标记和红色行动线表达合法性与威胁。
- 棋印页用动态图形说明作用；文字只确认对象和结果。

当一句说明超过一行时，先检查能否改为图形、位置、动效或状态变化，而不是继续压缩句子。

## 6. 当前词表

### 操作

`新局`、`续局`、`今日局`、`练手`、`继续`、`重开本局`、`回到标题`、`再开一局`、`再练一次`

### 状态

`开局`、`升变`、`王冠裂开`、`清场`、`护盾 -1`、`能量满`、`三连手`、`再走一手`、`败局`、`通关`

### 失败原因

`王冠碎了`、`手数用完`、`无棋可走`

### 教程

`点一枚亮棋`、`点一个亮格`、`红线是黑方下一手`

## 7. 审校清单

每次增加可见文字时逐项检查：

1. 删除这句后，规则是否仍可由画面判断。
2. 是否明确写出动作或结果。
3. 是否使用词表中的固定名词。
4. 是否出现同义替换、抽象词或宣传语。
5. 手机宽度下是否保持一行或可快速扫读。
6. 是否可能暴露开发、测试或生成过程。
7. 是否在实际界面状态中检查，而非只看文稿。
